# 空压机基线评估

air_compressor_labels.json包含30条AI依据原文初标的问题：20条development、10条validation。
覆盖型号、部件、安全、流程、故障码、高温、压力、电机、含油、振动、维护、工单和案例。
这是演示语料上的检索实验，不是工厂现场数据；标注需要人工复核。

每条标注包含章节名称、原文证据、问题分类与固定分组。运行脚本时将章节解析为当前知识库的
真实UUID，并校验证据存在。章节不存在或重分块后出现多条同名切片时会停止，要求复核标注。
不使用检索排名反推标准答案。只标注能回答具体问题的章节，推荐问题列表不算答案。

在项目根目录、fault-rag环境下执行：

```powershell
python backend/run_retrieval_benchmark.py --knowledge-base-id b7fc2ec3-201b-43cb-8435-3cde1c0d843a
```

完整实验会发送30条问题及候选演示切片到SiliconFlow重排服务，并可能产生API费用。
本地模式使用 `--local-only`，只比较向量与RRF，需要Embedding模型已经缓存在本机。
首次完整执行可能需要联网获取Embedding模型。

输出写入evaluation_reports下的新时间目录，包含语料快照、绑定UUID的标注、可提交API的请求、
逐题结果、模型配置及语料哈希、Markdown报告。只有生成report.md才代表完整执行成功。
失败目录可能只有语料与标注；不得将它们当成成功实验结果。

复核重点：同一问题可能有多个有效来源；避免只标一个章节而误判其他正确结果。
同一章节可能出现在两个分组，因此validation只是留出问题集，不代表跨文档泛化测试。
首次基线固定现有分块和参数；后续调参使用development，validation用于最后验证。
小标题未携带父级故障名称是待验证的召回问题，不应在基线前修改。
