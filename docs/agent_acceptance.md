# 设备诊断 Agent：首个验收场景

## 当前交付范围

已完成验收规格、设备/维修数据模型、演示初始化、两个只读工具及模型工具调用循环。
前端聊天默认发送 `mode: "agent"`；模型决定工具选择、参数和是否继续调用。
下面对话可在配置支持工具调用的模型后手动验收。当前依赖消息历史，尚无结构化诊断状态。

## 固定场景

演示时间固定为 2026-09-10。资料使用 `sample_documents/空压机维修知识库.md`，
设备、报警、维修记录及测量值均为虚构数据，不代表现场诊断结果。

1. 用户：“3 号空压机又报 E101。”
2. 后续编排层将设备编号明确为 `AC-003`（存在歧义时应追问），调用
   `get_device_history`。期望返回 AC-200、9 月 8 日 E101 报警、9 月 9 日换空气滤芯，
   并保留“尚未验证高温是否消除”，不能提前认定根因或排除滤芯问题。
3. 调用 `search_manual`，查询“AC-200 E101 高温停机 排查”，返回原文、文档、页码/
   章节、切片 ID、资料编号。设备历史提供事件事实，手册提供维修依据，不能互相替代。
4. 助手询问当前排气温度、已完成的检查及结果；不把历史温度当作当前测量值。
5. 用户：“排气温度 108℃，滤芯昨天换过，还是高温。”
6. 后续 Agent 更新本轮事实，结合手册给出有引用的下一步建议，避免机械重复换滤芯；
   “已更换”不自动等于“所有过滤系统原因已排除”。保留停机、断电、泄压等资料中的要求。

## 工具契约

- `get_device_history({device_id: "AC-003", limit: 10})`：这里的 device_id 是业务编号，
  不是数据库 UUID；最多返回 30 条，按发生时间倒序。无历史时返回成功及空列表。
- `search_manual({query: "AC-200 E101 高温", knowledge_base_id: "UUID", top_k: 5})`：
  top_k 为 1–10。复用 Dense/Sparse + RRF 和现有可配置重排，不调用生成模型。
- 工具统一通过 `DiagnosticTools.execute(name, arguments)` 调用，参数 Schema 可从
  `TOOL_DEFINITIONS` 获取，结果可用 `model_dump(mode="json")` 序列化。
- 调用方构造 `DiagnosticTools` 时绑定知识库；搜索参数不能扩大范围，设备也只能在
  此范围查询。这是工具范围限制，不替代未来 API 的用户鉴权。
- 返回 status、message、data。状态包括 ok、not_found、no_results、forbidden、
  invalid_arguments、timeout、error。错误结果不包含底层异常或连接信息。
- 候选命中不保证能够回答；引用编号仅对本次调用有效。最终答案的充分性判断属于后续阶段。
- 每次工具执行使用专用只读会话或无待提交写入的会话，串行调用；失败/超时会回滚。
  超时停止等待，但底层线程中的检索操作可能仍会完成。

## 初始化与验证

```powershell
conda activate fault-rag
python -m alembic -c backend/alembic.ini upgrade head
# 在现有前端创建独立演示知识库，上传演示手册，并完成分块及索引。
python backend/seed_demo_devices.py --knowledge-base-id <实际知识库UUID>
python -m pytest backend/tests/test_diagnostic_tools.py
```

初始化增加三台 AC-200 和五条模拟记录，可串行重复执行，不重复添加或覆盖数据；
若编号与非模拟设备冲突则失败。初始化脚本不自动上传手册、不调用外部模型。

## 本阶段自动检查

- 初始化重复执行后的数量一致；演示标记和关键维修结果保留。
- 同编号的跨知识库设备不可读，跨知识库检索被拒绝。
- 错误参数、未知设备、无命中、工具失败和超时具有明确结果。
- 检索工具能通过现有索引链路返回原文和可序列化的引用信息。

## 工具循环使用说明

重启后端及前端后，在已有演示设备和手册索引的知识库里提问：
“3 号空压机之前修过什么？”或“3 号空压机又报 E101”。
页面显示查询设备历史或维修手册的进度，模型收到工具结果后继续决策。
模型可以直接追问；没有强制每轮执行全部工具。工具记录原文不作为系统指令。
设备查询结果目前由答案中的设备编号和记录时间说明，原文侧栏展示维修手册。

后端普通和 SSE 多轮接口都接受 `mode: "agent"`。省略 mode 时仍为旧 RAG 模式。
本轮多次检索按 chunk_id 去重、累计编号；引用原文快照随最终回答保存。
工具进度包含调用 ID、名称、结果状态、耗时；执行记录和工具参数/结果摘要现已持久化，
可从回答下方或会话顶部查看。详见 [执行记录设计](agent_runs.md)。不保存模型内部推理。
工具错误可交回模型纠正参数或解释；模型失败、总超时、步数/工具数/上下文超预算则返回错误，
不保存半轮消息。不会自动重试收费模型请求。费用由决策次数和单次输出上限约束，未实现金额预算。

自动测试使用可控模型和本地检索替身验证循环及协议，不代表真实模型的诊断正确率。
完整场景的业务效果仍需人工验收；断线重连后不会恢复半途的工具执行。
